# 决策记录

## D001 不直接复刻原作，做同类玩法的原创游戏（2026-11-12，已确认）
- 方向：做中国大陆本土化的内容和玩法，持续迭代。
- 第一版就要原创，不能先照搬再慢慢改。
- 原作版权在 Kairosoft，直接照搬名称、美术、文本或数值，小游戏审核过不了，上线后也会被投诉下架。
- 玩法机制本身（经营、搭配加成）一般不受保护；名字、美术、角色、文本、数值表要自己做。

## D002 引擎选 Cocos Creator + TypeScript（2026-11-12，已确认）
- 2D 像素游戏用 Cocos 包体小、启动快，构建时可以直接选微信或抖音小游戏。
- Unity 导出成 WebGL 后首包大、启动慢，更适合 3D 项目（比如《23:40》）。
- 作为后端工程师，上手 TypeScript 成本低。

## D003 美术规格（2026-11-12，Claude 决策，用户自己画）
> ⚠️ 视角、尺寸、调色板三条已被 D014 取代（2026-11-13）。保留原文作为记录。
- 视角：正俯视（top-down），不用等距视角。等距视角画起来难度和工作量大约翻倍，首版不值得。
- 尺寸：地块 16×16 像素；小建筑 16×16，大建筑 32×32（占 2×2 格）；居民小人 8×12。游戏内整数倍放大（×3 或 ×4）。
- 调色板：固定一套 32 色（Lospec 上的 "Resurrect 32" 或同类），全游戏统一，自然就有统一的风格。
- 工具：Aseprite（约 20 美元，Steam 有售）；不想花钱就用免费的 Pixelorama。
- 节奏：M2 之前全部用纯色方块占位，等玩法验证好玩了再画，避免画了又废。
- 出图规范：每个建筑一个独立 png，统一导出到 assets/art/，后续用 Cocos 自动图集合并。
- 为什么选像素风而不是高清（2026-11-12 讨论）：一个人、非专业美术也能画出统一风格；包体小；动画成本低；"像素＋县城"有怀旧感。风险：小游戏大众用户更习惯高清卡通风。
- 做法：游戏场景用像素，UI 和文字用高清（清晰字体、圆角按钮），兼顾大众观感。
- 复查点：M3 可玩版本出来后，拿给 5～10 个非游戏圈的朋友试玩，再最终确认风格。代码中地块尺寸、缩放倍率放配置，不写死，保留换风格的余地。

## D005 视图平移缩放作用于"世界容器节点"，不移动相机（2026-11-12，Claude 决策）
- 做法：Canvas 下挂一个 World 容器节点，地图作为它的子节点；拖动/缩放只改 World 的 position 和 scale。
- 为什么不直接动相机：Canvas 组件在屏幕尺寸变化时会强行复位相机位置和 orthoHeight（`_onResizeCamera`），自己挪相机会和引擎抢控制权；而且相机一挪，同一台相机下的 UI 会跟着跑，但 HUD 必须钉死在屏幕上。
- 效果：视觉上与"相机平移缩放"完全等价，UI 天然不受影响，也不用和引擎较劲。
- 输入监听挂在全局 `input` 单例上，不挂节点：节点事件要先做命中测试，得保证节点尺寸和屏幕一致；全局输入直接拿原始触摸，微信/抖音/浏览器三端行为一致，T102 做点选地块时也不受 UI 遮挡影响。
- 缩放：双指捏合支持连续缩放，松手吸附到配置里的整数倍档位（D003 的像素对齐要求）；桌面调试用滚轮换档。
- 实测（2026-11-12，CDP 驱动无头 Chrome + 触摸模拟）：拖动、滚轮、双指张开/收拢全部通过，缩放正确在 [2,4] 区间夹紧；网格线像素间距恒为 48px（16×3），无半像素发虚。

## D006 场景文件极简，节点全部代码生成（2026-11-12，Claude 决策）
- `.scene` 里只放 Canvas + 相机 + 一个挂 `GameRoot` 的空节点，其余节点运行时用代码搭。
- 原因：Cocos 的 .scene 是引用式的 JSON，手写和多人合并都容易冲突；把布局放代码里，改结构不用碰场景文件，也方便之后换设计分辨率。
- 代价：不能在编辑器里所见即所得地摆 UI。现阶段（占位色块，D003）可接受；等 UI 复杂到需要可视化调布局时再改，届时可以引入 Prefab。

## D007 资源配置统一走 resources bundle 的 JSON（2026-11-12，Claude 决策）
- `assets/resources/config/world.json` 存地块尺寸、网格大小、缩放档位、调色板；代码里有 `DEFAULT_WORLD_CONFIG` 兜底，读不到就告警并用默认值，保证不因为配置问题白屏。
- 遵守 CLAUDE.md "数值全部放配置表"：以后建筑价格、收益、加成同样放这里，按 `config/xxx.json` 分文件。

## D008 地块数据与渲染分离（2026-11-12，Claude 决策）
- `TownModel` 只管"哪一格被谁占了"，完全不碰渲染；`BuildingLayer` 只负责把模型画出来。
- 坐标约定：`col` 从 0 开始从左往右，`row` 从 0 开始从下往上；多格建筑只记左下角，其余格子指向同一个 `PlacedBuilding` 对象。
- 为什么这么分：以后加存档（序列化 model 即可）、加收益结算、加 PRD 第 6 节的特色街道组合判定，都只读 model，不用动画面代码。渲染换贴图时也不用改规则。
- `canPlace` 自己做边界和占用的双重检查，`place` 再调一次 `canPlace` 兜底，保证任何调用路径都不可能放进非法位置。

## D009 点击与拖动用位移阈值区分（2026-11-12，Claude 决策）
- 手指按下记起点，松手时累计位移小于 12 像素算点击，否则算拖动。
- 没有监听 `MOUSE_UP` 单独做点击，因为真机上只有触摸，一套代码三端通用。
- 双指一旦开始缩放就立即作废本次点击，否则捏合完松手会误放一栋建筑。
- 落在 UI 上的手势不传给地图：UI 面板建好后调 `InputGuard.add(节点)` 登记，地图在触摸开始时问一句"这里被占了吗"。这是 D005 选全局 input 之后必须补的一环。

## D010 底部建筑栏做成横向可滑动（2026-11-12，Claude 决策）
- 竖屏只有 720 宽，15 种建筑一屏放不下（每个按钮 112 宽 + 间距，总宽远超屏幕）。
- 不做分页、不做多行网格：横向滑动最接近手机原生列表手感，也最省竖向空间（竖向要留给地图）。
- 布局容易算错的地方：按钮 x 要加半个按钮宽，否则第一个按钮会有一半跑到屏幕外；滚动量范围是 `[0, 内容宽 - 屏宽]`，不是 `[-(内容宽-屏宽)/2, 0]`。
- 滑动和点击的区分同样用阈值：拖动超过 6 像素就标记为滑动，松手时不触发按钮点击。

## D011 32 色调色板定稿（2026-11-12，Claude 决策）
- 色卡：`docs/art/palette.png`；色值：`docs/art/palette.json`；规范：`docs/ART_SPEC.md`。
- 32 色分四组：中性/深色、绿/土、暖色、冷色。每组内按明度排列，方便取"同色系深两档"画轮廓。
- 现有 `world.json` 和 `buildings.json` 里的 19 个颜色全部能在这 32 色里找到对应，不用改配置。
- 规则只有三条：只用这 32 色、不画渐变和半透明、每栋建筑外描一圈深色轮廓。这三条是画风统一的全部保证。
- 不采用"Aseprite 里随便取色"的做法：一个人画 15 栋建筑，靠自觉很难保持统一，锁死调色板是最省力的约束。

## D012 像素图导入必须关掉过滤（2026-11-12，Claude 决策）
- Cocos 图片资源默认是线性过滤（`linear`），16×16 的图放大到 ×3 后边缘会被插值成模糊的过渡色，像素风直接毁掉。
- 必须改成 `nearest`（导入器里的取值是 `'none' | 'nearest' | 'linear'`，字段名 `magfilter` / `minfilter`），Mip Maps 关掉，Wrap Mode 用 `clamp-to-edge`。
- 这条容易漏，因为默认值看起来"能跑"——只是糊。所以写进 ART_SPEC 的导出清单，每次导图都对照一遍。
- ~~待验证~~ → 已由 D013 改为代码兜底，导入设置不再是必须项。

## D013 建筑贴图按 id 自动加载，过滤方式由代码强制（2026-11-13，Claude 决策）
- 图放 `assets/resources/art/buildings/<id>.png`，启动时用 `resources.getDirWithPath` 列出目录里真实存在的图再加载，缺图不发请求、不报错，直接回退色块。贴图和色块可以混在一张地图上，美术能一张一张往里加。
- 不依赖导入设置保证锐利：加载原始 `ImageAsset`，自己建 `Texture2D` 并设 `NEAREST / 无 mipmap / CLAMP_TO_EDGE`，`SpriteFrame.packable = false`（动态合图的纹理是线性过滤）。D012 那条"每次导图都要手动改"容易漏，改成代码兜底后漏了也不会糊。
- 代价：同一张图不能直接拖到编辑器场景里用（那边还是导入设置）。目前建筑全部由代码生成，不受影响；以后要在编辑器里摆 UI 图时再按 D012 改导入设置。
- `BuildingLayer` 拆成三层：色块 Graphics（本节点）→ 精灵子节点（按 uid 复用，只增删变化的）→ 预览 Graphics。预览单独一层后，鼠标移动时不再整张重画建筑。

## D014 改为等距视角，画面对标同类像素经营游戏（2026-11-13，用户拍板）
- 起因：用户放了 6 张同类游戏截图到 `reference/`，要求"至少做出类似的东西"。正俯视 16×16 在规格上就到不了那种密度——只看得到屋顶，招牌、门窗、楼层都没地方画。
- 视角：等距 2:1，菱形地块 32×16。格子坐标 gx 往右下、gy 往左下，(0,0) 是地图最上角。换算全在 `core/IsoMath.ts`，纯函数。
- 地图 40×40（等距地图的外接矩形永远 2:1，竖屏下 24×40 会上下露底；40×40 在 ×2 时 2560×1280，能上下左右拖）。默认 ×4、档位 2/3/4/5（同日用户再要求放大，×4 约 2.1pt / 美术像素，一屏横向约 6 格；更早一版是 ×3，再更早 ×2：换算到真机，×2 时一个美术像素约 1.1pt，比参考游戏的 1.3pt 小，店铺看不清；×3 约 1.6pt）。
- 建筑图：宽 = (w+h)×16，高随意；图的底边中点对齐占地菱形的最下顶点。宽度不对时代码回退色块并警告。
- 前后遮挡：每次重画按占地中心的 gx+gy 排序（`IsoMath.depth`）。对互不重叠的 1×1/2×2 混排正确；以后有 3×1 之类的长条再换拓扑排序。
- 马路不当"建筑"画，进地面层，按四邻自动选 16 种拼接图之一（`buildings.json` 里 `"flat": true`）。地面草地和马路在同一张图集 `ground.png`，1600 格合批成一次绘制。
- 调色板 32 → 48：原 32 色全保留，补 16 个色阶（亮暗面各要一档）。
- 出图方式：`docs/art/gen/iso.py`（等距长方体 + 墙面坐标系，窗户/门/招牌按"墙上第几列、离地几行"画），每张图的脚本在 `sample.py` 等文件里。脚本保存时逐像素校验：只能是调色板颜色、不能半透明。好处是 15 栋楼光照方向和描边完全统一，改一个参数全部重出。
- 原创约束不变：参考图只用来对标画面密度和氛围，建筑、人物、UI 都不照着画。`reference/` 已加入 .gitignore，不进仓库。
- 代价：前两批 10 张正俯视图作废（源文件移到 `docs/art/legacy-topdown/`）；以前 TASKS 里 T203～T208 的产出不再使用。

## D015 建筑门面朝向按马路自动选（2026-11-13，Claude 决策）
- 等距下只看得到两面墙：左下墙（朝 +row）和右下墙（朝 +col）。每栋有门面的建筑出两张图：`<id>.png` 门面在左下墙，`<id>_r.png` 门面在右下墙。
- 规则（`BuildingLayer.facesRight`）：左下边挨着马路 → 默认图；否则右下边挨着马路 → `_r`；都不挨 → 默认图。马路增删后重画时会重新判断。
- 不用"把图左右翻转"：翻转会让光从右上来，和别的楼对不上。脚本里按朝向重画一遍，墙色仍是左亮右暗；只有门口小道具是翻转贴的（盒子左右对称，翻转后位置正好）。
- 局限：马路在建筑背后（左上或右上）时门面没法对着路，只能朝镜头。这是等距视角本身的限制。
- **修订（2026-11-13，用户发现朝向会乱跳）**：原来每次重画都重新判断，导致先盖店后修路、拆路时已有建筑会突然换朝向。改为：
  - 朝向存在 `PlacedBuilding.facing`（数据层，以后进存档）。放下时四周有路就按上面的规则定；没路先留空（显示默认图），第一次挨上路时定一次。定了就锁住，之后修路拆路都不变。
  - 玩家手动换：没选建筑、没开拆除时点一下已有建筑，在两个朝向间切换（只对画了 `_r` 图的建筑生效，行道树和广场点了没反应）。解决路口转角想朝另一条路的情况。

## D016 建筑图打成一张图集，散图可覆盖（2026-11-13，Claude 决策）
- 出图流程：`sh docs/art/gen/make.sh` → 各脚本把单张图写到 `docs/art/build/`（进 git，方便看和手改）→ `pack.py` 货架式装箱成 `resources/art/atlas.png`（1024 宽，高补成 2 的幂，每张留 2 像素透明边）+ `atlas-frames.json`。
- 游戏只加载图集，所有建筑共用一张纹理，前后排序打乱也能合批。实测地图 85 → 3 次绘制（地面 2 + 建筑 1），和打图集前截图逐像素一致。
- 没用 Cocos 自带的自动图集：它的纹理过滤走导入设置，我们的像素锐利是靠代码自建纹理保证的（D013），自带图集绕不过去。自己打包也就 40 行。
- `resources/art/buildings/<id>.png` 散图仍然支持，同名时覆盖图集那一帧——手改一张图想马上看效果，不用重新打包。正式提交前还是要改 `docs/art/build/` 再跑 make.sh，否则包里一图两份。

## D017 道路两种 + 会动的东西（2026-11-13，用户提出道路分级，Claude 实现）
- 道路分「土路」(`dirt-road`，开局可用) 和「城市道路」(`road`，县城解锁)，统称道路。`buildings.json` 用 `road: dirt|city` 区分，`unlockLevel` 记解锁等级。拼接时两种互相算连通，接头处各画各的，不断开。
- 地面图集 36 帧：0～3 草地，4～19 城市道路，20～35 土路（`docs/art/gen/ground.py`）。
- 会动的东西（`world/LifeLayer.ts`）：节点挂进建筑层同一个父节点，用同一个排序键 gx+gy，所以会被前面的楼挡住；图和建筑在同一张图集里，交错排序也能合批（加了 40 个小人后绘制次数只多 2）。
- 汽车只走城市道路，行人和电动车哪种路都走——这让"升级成城市道路"在画面上有直观收益。
- 纯表现层，不碰经营数值。金币现在随机从挨着道路的店铺冒出，M2 有收入结算后改成按真实收入触发。
