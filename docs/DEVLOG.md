## 2026-11-16 施工进度条一出现就半满（bug）
- **现象**（用户真机反馈）：刚放下楼，进度条就已经一半。
- **原因**：`Simulation.constructionProgress` 的公式把画面层传进来的 `dayProgress`（本月已经走到哪儿）当成「开工后干了多少」：`(total - left + dayProgress) / total`。楼刚放下 `left = total`，前半项是 0，后半项直接把这个月已过去的部分算成工期。下午放下 1 天的楼就是 50%。测试里全在 `dayProgress = 0` 时开工，所以一直没暴露。
- **连带问题**：完工只在月初结算、且不认开工时刻——快天黑才开工的 1 天楼，0.1 个月就完工，越晚开工盖得越快。
- **做法**：施工 / 翻盖记录加 `startAt`（开工那一刻的绝对时刻 = 月 + 当天进度，0..1）；`SimApi.onBuilt(uid, defId, dayProgress?)` 多传一个参数，GameRoot 传 `DayClock.progress()`。进度 = (现在 − 开工) / 实际跨度，跨度取到「第一个 ≥ 开工 + 工期的月初」，所以进度条不会先顶到 100% 干等。老存档没 `startAt` 时 `normalizeSimState` 按已干的整月数倒推。
- **验证**：模拟测试 90/90（新增 2 条：月中开工从 0 起算；开工越晚完工不会更早）；tsc 项目代码零错误。
- **待集成**：真机看一眼 1 天工期楼月中放下时的进度条起点和完工时刻。

- **问题**：3D 版里行人、车还是 2D，永远画在楼上面，走到楼后面会穿帮。
- **做法**（`World3D.drawActors`）：每个人 / 车画成**面向相机的纸片**。纸片和屏幕平行，整张的深度 = 脚下那点的深度，所以前面的楼会挡住它，后面的楼不会切到头，效果和 2D 按脚下排序一样。尺寸：屏幕上 1 个 2D 世界单位 = 3D 里 1/(hw·√2)。影子平铺在地上（屏幕上高 sh 的影子在地上长 2·sh），着地点按 settle 往远处挪。一张纹理一个动态网格（`createDynamicMesh` + `updateSubMesh`，最多 600 块），先铺影子再按远近画身体，一次绘制。材质是 ground-unlit 同一个 effect 的 technique 1（半透明：深度测试、不写深度），顶点色带出门淡入、进门淡出。
- **LifeLayer**：`use3D` 时 2D 精灵不显示，但照样算位置、选帧（追踪、气泡、点击都还按 2D 节点）；`actors3D()` 每帧交出 `Actor3D` 列表。`?flat2d` 不受影响。
- **T550 小改**：顶栏「每个成年人房租 ¥X/月」（实际只收成年人）；住满不标红，标题写「住户（已满）」。
- **验证**：tsc 零错误；worktree 命令行出 web-mobile，无头截图：正常视角、转 180° 后，早餐铺 / 县发展中心后面的人被楼和招牌挡住（`docs/ui-acceptance/t540f-actors-occluded.png`），影子在脚下，页面无报错。**没验证**：中间角度（扭转一半）、汽车 / 摩托在 3D 里的样子（开局没人有车）、微信真机。
